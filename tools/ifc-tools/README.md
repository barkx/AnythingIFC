# ifc-tools

Python CLI that runs on the owner's PC: downloads projects from the app, prepares them for modelling
and checks the finished IFC. See PLAN.md §8–9.

Run from the repo root (uv downloads Python 3.12 automatically — `ifcopenshell` wheels lag new Python releases):

```bash
npm run tools -- list                 # projects waiting for work (--all for everything)
npm run tools -- pull <id>            # download inputs to C:\IFCWiseData\jobs\<id>\ and run prepare
npm run tools -- prepare <id|folder>  # re-run preparation, re-render PROMPT.md
npm run tools -- validate <id|folder> # check output/model.ifc, write output/summary.json (exit 1 on errors)
npm run tools -- build <id|folder>    # Route B: output/model-spec.json -> output/model.ifc, then validate
npm run test:tools                    # pytest
```

## Settings

Copy `.env.example` to `.env` in this folder (gitignored):

| Variable | Purpose |
|---|---|
| `IFCWISE_APP_URL` | `http://localhost:3001` locally, `https://app.ifcwise.com` in production |
| `IFCWISE_ADMIN_TOKEN` | same value as the app's `ADMIN_API_TOKEN` |
| `IFCWISE_DATA_DIR` | where job folders go, default `C:\IFCWiseData` |
| `ODA_CONVERTER` | optional: path to `ODAFileConverter.exe` to turn DWG into DXF |

## Job folder

```
<IFCWISE_DATA_DIR>\jobs\<id>\
├─ job.json      project data from the app (no email)
├─ input\        uploaded files
├─ prepared\     <name>.geometry.json per DXF/DWG, pages\*.png per PDF
├─ PROMPT.md     instructions for Codex / Claude — start here
├─ revit\  bonsai\
└─ output\       model.ifc, summary.json (written by validate), assumptions.md, preview.png
```

## What `prepare` extracts from DXF

Per layer: `lines` `[x1, y1, x2, y2]`, `polylines` `{closed, points}`, `arcs` (circles and arcs), `texts`
`{text, at, height}`, `inserts` (block references — often doors and windows) and `dimensions`, plus the
drawing `units` and `extents`. Coordinates are in drawing units, rounded to 4 decimals.

## What `validate` checks

Errors: file parses; schema IFC4; exactly one `IfcProject` and `IfcSite`; at least one `IfcBuilding` and
`IfcBuildingStorey`; length unit matches the project (m or ft); at least one `IfcWall`; every element is in
a storey. Warnings: no `IfcSpace`, no openings, no element types. `summary.json` follows `ModelSummary` in
`packages/shared`.

## Route B model spec

`build` (`src/ifc_tools/builder.py`) turns `output/model-spec.json` into IFC4 with typed walls, slabs, a flat
roof, openings filled with doors/windows, and spaces with floor-area quantities. Format and reference:
module docstring and `docs/SOP-conversion.md`.

## Test fixture

`tests/fixtures/simple-house.ifc` is generated by `tests/fixtures/make_simple_house.py`
(two storeys + roof, 10 walls, 3 slabs, 4 spaces).
